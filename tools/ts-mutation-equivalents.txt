# Adjudicated EQUIVALENT mutants in the TypeScript client: surviving
# mutations that no test can kill, because the mutated code is observationally
# identical to the original.
#
# Format, one entry per mutant (docs/specifications/020-a-mutation-adjudication-names-the-code-it-excuses.md):
#
#   <file>  <MUTATOR>  offset=<n>  span=<n>  nth=<n>  copies=<n>  <replacement>
#       code: <the line the mutant starts on, trimmed>
#       <reason>
#
# `offset` is Stryker's column, in UTF-16 code units, within the trimmed line;
# `span` is how many UTF-16 code units the mutant covers, start to end, leaving
# out each line's indentation and trailing blanks and counting a line break as
# one; `copies` is how many lines of the file hold that code, and `nth` which of
# them the entry names, counted from the top. The replacement runs to end of
# line because it can contain spaces. The code line and the reason are both
# required — a bare entry is a parse error, and so is a reason with no entry
# above it. A line whose first character is `#` is a comment.
#
# The REPLACEMENT is part of the key for a reason found the hard way: Stryker
# emits both `-> true` and `-> false` for one ConditionalExpression at one
# location, and without it those two collapse into a single entry — so
# adjudicating the harmless one silently excuses the other. The gate's own
# duplicate check caught that on a ConditionalExpression in
# client/src/player.ts.
#
# ------------------------------------------------------------------------
# READ THIS BEFORE ADDING AN ENTRY.
#
# An "equivalent" verdict asserts that NO test can ever kill this mutant, so
# it forecloses writing one. A wrong entry is therefore WORSE than an
# unadjudicated survivor: it converts a real gap into a permanently excused
# one, in writing, with a confident-sounding justification.
#
# That is not hypothetical — see tools/mutation-equivalents.txt, where four
# mutants were adjudicated on the Go side and TWO were wrong. The reasoning
# was about JSON marshalling when the actual observable was reflect.DeepEqual
# over decoded structs, where nil map != empty map. A two-line fixture killed
# both.
#
# The test to apply, learned from that mistake: do not ask "is the output the
# same?" Ask "is there ANY observable — under deep equality, under identity,
# under undefined-ness, under iteration order, under what reaches the DOM —
# that distinguishes them?"
#
# An empty file is the GOAL STATE, not a problem. Prefer killing a mutant to
# excusing it; reach for an entry only when the mutation genuinely cannot be
# observed.
#
# AN ENTRY NAMES CODE, NOT A LINE. A line added or removed above a mutant moves
# it and leaves its entry valid. A copy of its code added or removed anywhere in
# the file changes `copies`, and one above it changes `nth` too. Two different
# mutations on one code are two separate claims, by mutator and by replacement.
# A stale entry — one whose key no surviving or timed-out mutant has — is a
# hard error, and the gate's line for it says where in the same run to look
# before the entry is re-keyed or removed. An edit to the code itself leaves
# the entry naming code that no longer stands, and the gate fails:
# re-judge the reason against the new code before writing the new code line.
#
# TWO ADJUDICATIONS WERE FILED AND WITHDRAWN during the dm-hands-and-retraction
# arc (Task 4, 2026-08-30): one on view/player.ts and one on view/spectator.ts,
# both `?? ""` equivalence claims for the same expression shape
# (`Object.keys(st.Scenes).sort().at(-1) ?? ""`), both eventually falsified by
# the same technique — a hand-built state where st.Scenes has no own keys but a
# prototype answering "" with a real scene, making the fallback string
# observable after all. Notable because the second one was re-keyed and
# re-confirmed TWICE (fix rounds 1 and 2) without anyone re-reading its claim
# against the first, which had just been disproved in the same round. Full
# correction and the killing tests are in each file's own section below; neither
# carries an entry now.
#
# Fix round 1's own review separately found eight UNADJUDICATED survivors (not
# stale entries) in that arc's new code, accounted for here rather than left an
# open question: six were killed with tests added that round — see
# player.test.ts's "no scenes at all means no toggle", "the current scene is the
# lexicographically GREATEST id" and "the toggle's class and label reflect
# whether doors are currently armed" — one was adjudicated equivalent at the
# time (the view/player.ts `?? ""` claim above, later disproven and withdrawn),
# and one was removed outright as dead code rather than tested or excused:
# spectator.ts's renderGrid losing its unreachable `doorsArmed = false` default
# parameter (a mutant with no observable is still a mutant if nothing forces the
# default to be read; deleting it removed the mutant).

Verified by hand-applying the mutant (suite stayed green, 673/673) and by running both versions over 439,040 (scene, camera, cell, viewport) combinations — scales 0/negative/1e9/±Infinity/NaN, offsets ±1e9/±Infinity/NaN, cells 0/negative/fractional/Infinity/NaN, viewports 0/-1/Infinity/NaN, with and without terrain — for zero divergences. ONE distinguisher exists and is recorded rather than hidden: defining numeric X/Y/Width/Height on String.prototype makes the fallback element draw (measured, not supposed). That is not an input to planScene — it is a redefinition of the language underneath it — and a test doing it would pin the literal contents of a defaulting expression rather than any behaviour of the planner, while leaking a polluted builtin into every other test sharing its process.
